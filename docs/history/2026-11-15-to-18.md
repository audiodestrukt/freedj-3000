## 1. Tests for what had none (2026-11-15)

A coverage run (`cargo llvm-cov`, first baseline 63.8 % of lines) showed the
app's Link threads, LINK loads and keyboard input at or near 0 %.  Dan: "ok
keep writing tests".

- `66d12cb` The three Link listeners were bodies of socket loops; their
  logic moved into `AnnounceRx` / `BeatRx` / `StatusRx` (`on_packet(data,
  addr) -> Vec<Reply>`) so tests feed them packets.  15 tests: master
  tracking, handoff by the Mh byte, holding master against a higher counter,
  yielding, beat twins, sync control, CDJ-3000 positions, the peer table,
  defending our player number.  A deliberate break of the handoff rule made
  two of them fail, so they catch regressions.
- `5c89481` The sender's master rules (`Handoff::tick`,
  `forget_silent_master`, `status_replies`): 9 tests.
- `fd5d6bd` LINK load end to end on loopback, with non-standard ports
  (`LinkPorts`), because this box's own media server holds the real ones.
- `ca74360` A virtual ALSA MIDI port plugged, played, unplugged and
  replugged; `controllers.toml` over the presets.

Coverage after: 67.2 % (app 61.4 %, `prodj.rs` 49 → 70 %).

## 5. The Pi as an appliance: boot to the deck

Dan: "is there a way for me to get freedj to boot on power on", then
"Do we need to start the desktop at all?", then "I want to make sure we keep
full gpu acceleration".

- `718bb78` First version: desktop autologin + XDG autostart; and
  `OPENDECK_FULLSCREEN=1` made to work on the wgpu renderer (it was SDL-only).
- `619b9b4` No desktop: a systemd service runs the deck in **cage** (a
  one-app Wayland kiosk) on tty1 as the player's user, with a PAM session
  (pam_limits for the real-time audio limits).  **Why cage:** the GPU
  renderer (wgpu / Vulkan) needs a display server for its window; the SDL
  renderer can draw straight to KMS but draws waveforms on the CPU.  Dan
  wants full GPU, so cage stays (decision recorded in memory).
- Plymouth boot splash, handed to the deck with `plymouth quit
  --retain-splash`; `46a7e59` made it **audiodestrukt's wordmark**
  (`make_splash.py`, from audiodestrukt.com's brand: the transistor mark,
  "audio" grey, "destrukt" lime).  Dan: "I want my audiodestrukt branding on
  the loading screen".
- Sound: ALSA's default pointed at the USB card.  The first boot failed:
  trixie's alsa-lib rejects a card name in `defaults.pcm.card` ("card is not
  a string"), the deck found no device and exited; fixed with
  `pcm.!default { type plug; slave.pcm "hw:CODEC" }`.
- Pointer hidden (`OPENDECK_HIDE_CURSOR`) plus a transparent cursor theme
  for cage, which draws its own until the mouse moves over the deck.
- `bfc5744` The USB automount installed with the appliance (no desktop =
  nothing mounted sticks; Dan: "usb isn't showing up in source").

Booted on the test Pi 5 (Raspberry Pi OS trixie, 7" DSI panel, UCA202):
~15 s from power to the deck, 1 % CPU idle.  Recipe:
`deploy/pi/autostart/README.md`.

Found on the way: the Pi's supply offers 3 A and logged an undervoltage at
boot (the official 27 W one is needed); once the UCA202 dropped off in that
dip and the deck, finding no device, restarted until systemd gave up.

## 6. The hardware deck mode (`6eaad3a`)

bars aren't working, we went through this before", then "the real cdj-3000

  fill, top keys, no pointer).  Dan: "let's try to create a flag or
  something for it".  The iPad and desktops are untouched.

## 9. CDJ-3000 behaviour, checked on two emulated units; PR #54

PR #54 (draft, mortalinstrument) adds the WAVEFORM view in the phase-meter
slot, INFO player tabs and a MASTER release.  Dan: "rebase it now and I want
to verify that master key giving up the role is what the cdj3000 does".

- Rebased onto main (three files in conflict: both sides had added code)
  and pushed over SSH (the OAuth token may not touch workflow files).
- Two cdj3k-emu units (firmware 3.22) on the private bridge `djlink0`, plus
  OpenDeck as a third player, traffic captured through QEMU's QMP
  (`filter-dump`).  Findings, `docs/reference/cdj-3000-master-and-waveform-view.md`
  (`7ea6251`):
  - **MASTER on the master hands the role to a playing player** (the handoff
    byte), and does nothing if no other player plays.  Not "release to
    nobody".
  - **The WAVEFORM view is real** (manual p.24, item 11) and draws the
    **tempo master's** waveform with its beat ticks; "MASTER PLAYER" on the
    master itself.  The unit **prefetches** the master's analysis (PWV7,
    PWV5, detail waveform, beat grid, PQT2, cues) the moment that player is
    playing and master; opening the view sends nothing.
- PR #54 updated to match (`69bb4fa` on its branch): `hand_off_master`
  replaces the release; the view follows `master_player`, not the last beat
  sender.  Tests for both.

## 10. OpenDeck as tempo master: why a CDJ won't show its waveform

With OpenDeck as master a CDJ showed the "4" badge and no waveform.  Tried,
with both emulated units watching:

| OpenDeck serving | The CDJs did | Analysis fetched |
|---|---|---|
| a plain folder | LOOKUP `PIONEER` (not found), dbserver setup, at most one metadata request | no |
| an empty `PIONEER/rekordbox` | looked for `djprofile.nxs` and `CDP`; both asked the metadata | no |
| plus the title row's `0x0100_0000` flag | the same | no |

OpenDeck's status already matches a CDJ's.  The likely missing piece is a
real rekordbox export (`export.pdb` + ANLZ) of OpenDeck's library: a larger
project, and the same thing that would make OpenDeck's library look like a
rekordbox stick to every player.  The flag was kept (`2d1ce27`; it is what a
CDJ sends).

## 11. The iPad that started muted

Reports of the iPad app starting silent.  The mechanism, explained by the
developer who fixed it: no audio-session category, so iOS used SoloAmbient
and **the ring/silent switch muted the app**; PR #50 set Playback.  It is in
0.3.28 (live since 2026-11-16); 0.3.10, live before, did not have it, so
the reports fit.  Lower-priority hardening noted in `docs/TODO.md`: iOS never
rebuilds a dead output stream (Linux does), and session errors go only to
the system console.

## 12. Pi dropouts with a USB interface (`bc6a482`)

Full write-up: [`../bugfixes/pi-usb-audio-dropouts.md`](../bugfixes/pi-usb-audio-dropouts.md).
In short: the ring was kept half full by back-pressure sized for 0.25x, and
the UCA202's late callbacks ask for two 1 103-frame periods at once; now the
room waited for follows the speed.  Proved on the Pi and by a test (13
underruns in 2.5 s before, 0 after).

## 14. Latency and jog tests

Dan: "we need integration tests for the cue/play button latency, hitting cue
should start playing immediately within a few ms".

- `cue_latency_tests`: a stand-in low-latency interface (128 frames, 2.9 ms)
  records every buffer; CUE held, PLAY from paused and CUE again reach sound
  in **8.7 ms** (three device buffers), budget 20 ms.
- Dan's DJ2Go report ("vinyl mode … the waveform moves but the output is
  muted") did not reproduce: a turn is heard paused and playing at a
  hand-turned rate.  A hold-and-scrub change was tried and backed out (it
  fixed nothing proven).  Most likely the dropout bug chopped the scrub to
  silence; retest pending.  `6fd8b68` keeps the paused-scrub test and moves
  the wheel-idle check out of the frame loop so tests run it.
- Two parallel-run flakes fixed: the output-gain test vs. test decks resetting
  the global gain (a lock), and a loop test reading the heard position the
  instant the loop wrapped.
- Dan: "do these tests run for all the different platforms"?  No: Linux on
  every push, Windows at `win-v*` tags; macOS, iOS, Android only build.
  Dan: "we probably only need to run the platform tests when we do a tagged
  release" (TODO).

## 15. Product ideas and scope

`docs/design/product-ideas.md` (`5ace630`, `b7a3c84`):

1. A powerful media server with light decks; it splits stems in real time and
   streams them; maybe a mixer.
2. One deck with banks A/B/C/D, MPC-style, maybe an output per deck.
3. OpenDeck on iOS as a stem source for an OverCue-modded CDJ (the existing
   serving-split-stems proposal; on hold since 2026-11-15).
4. A battery-powered Pi deck: measured 4.7 W idle on the board's rails,
   ~8-9 W playing with the panel, ~15 W splitting stems; a 20 000 mAh 5 V /
   5 A PD bank gives ~7 h.
5. Elektron-style page-aware encoders beside the screen: **a different
   product**.  Dan: "this is for another product basically, we specifically
   don't do mixer features on this version."  OpenDeck stays deck-only: no
   EQ, filter or channel gain (recorded in memory).
